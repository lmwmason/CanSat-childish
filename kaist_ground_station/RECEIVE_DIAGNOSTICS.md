# 수신 지연과 GPS 고도 검증

웹 지상국은 직렬 수신을 20ms 간격의 별도 루프로 구동한다. 서비스 접근은
하나의 잠금으로 직렬화하고, 바람 계산·JSON 생성·카메라 PNG 인코딩은 그 잠금
밖에서 수행한다. 화면 갱신이 느려져도 수신과 원시 기록은 계속된다.
바람 계산 캐시는 복사된 객체의 주소 대신 실제 GPS 입력으로 비교한다.
CPU·디스크·운영체제 전체가 멈추는 상황까지 보장하는 구조는 아니다.

`76 00 31 00 00`은 정상 카메라 설정 응답으로 처리한다. 이 응답을 오류에서
제외해도 원시 로그에서 이미 빠진 사진 바이트가 복구되지는 않는다.

## 다음 실기 시험

저장소 루트에서 기존 지상국 프로세스를 종료한 다음 실행한다.

```bash
./kaist_ground_station/run.sh live
```

화면 없이 수신만 비교하려면 다음 명령을 사용한다. 같은 어댑터를 두 프로그램이
동시에 열지 않는다.

```bash
python3 -m kaist_ground_station.tools.monitor --duration 180
```

카메라 ON/OFF 비교는 같은 장소·거리·안테나 방향에서 수행해야 한다.
정지 상태에서도 사진이 잘리면 거리 변화만을 원인으로 볼 수 없다.
수신 공백이 어느 장비에서 시작됐는지는 PC 수신 로그 하나로 확정할 수 없다.

GPS는 탁 트인 곳의 같은 지점에 고정해 충분히 안정화한 뒤, 움직이기 전후의
고도·위성 수·HDOP를 비교한다. GGA 고도는 해수면 기준이며 지면에서의 높이가
아니다. HDOP는 수평 지표이고, GGA fix=2도 수직 정확도를 보장하지 않는다.
출발/착륙 사건 시각과 독립 고도계가 있어야 비행 중 오차를 정량화할 수 있다.
원시 고도를 강제로 단조 하강시키거나 착륙점에 맞춰 덮어쓰지 않는다.

## 검증 범위

가상 직렬 포트 시험은 계산을 의도적으로 차단한 동안에도 수신·파싱·원시 파일
저장이 계속되는 것을 검사한다. 실제 비행 로그 재처리는 GPS/IMU/ATLM/DTLM과
완성 사진 바이트가 수정 전과 동일한지 비교했다. 두 시험 모두 실제 무선 품질이나
GPS 측정 정확도가 개선됐다는 증거는 아니다. 다음 실기 수신으로 따로 확인한다.
