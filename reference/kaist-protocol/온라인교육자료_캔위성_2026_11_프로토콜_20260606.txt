캔위성 기본 키트 – 0. 프로토콜 ( 시리얼 통신 )
   RS232C 시리얼 통신 규약 (방법)
      Recommended Standard system for serial communication
      신호적으로 0 과 1 을 이용하여 데이터 1 비트 사용
      기본 특징 (예) 115200, N, 8, 1 -- 설정에 따라 변동 가능 )
       • 전송 속도 (bps)        : Bit Per Second 초당 전송 비트 수 [ 115200 ]
       • 패리티                 : 전송 오류 점검을 위한 추가 비트 수 [ N : 없음 ]
       • 전송 비트수             : 한번에 보내는 비트 수                 [ 8 : 8비트 전송]
       • STOP 비트            : 멈춤을 위해 필요한 시간                [ 1 : 1 비트 시간 멈춤]
      한번 보내는 시간 도표
       • 보통 ‘1’ 를 유지하고 있다가 ‘0’ 로 떨어지는 순간 부터 시작
       • 같은 시간 간격으로 비트 값을 전송 비트수(8) 만큼 전송
       • 전송 이후 최소 STOP 비트 수 만큼 ‘1’ 유지 후 다음 데이터 전송 가능

캔위성 기본 키트 – 1. 프로토콜 ( to 통신부 )
   통신부(Firmtech FB775AS) 와의 프로토콜 ?
      RS232 시리얼 통신
       • 설정시 기본 값 9600, N, 8, 1 임 ( 스위치나 점퍼 핀 사용 )
       • 캔위성은 115200, N,8,1 을 이용하여 사용
       • 한 번 설정되면 설정을 저장하고 있음.

      블루투스 ( 네이버 지식 참조 ) 사용
       • 근거리 무선통신 규격의 하나
       • 반경 10~100m 안에서 각종 전자 정보 통신 기기를 무선으로 연결, 제어하는 기술 규격
       • 2.45Ghz 주파수를 이용
       • 전세계 2000여 개 업체가 가담. 무선 네트워킹의 세계적 표준

      초기 설정 사용 사용
       • Firmtech FB775AS의 경우 UART 를 통한 명령으로 설정 후 사용
       • 시리얼 통신은 115200, None, 1 로 설정
       • 동작모드는 외부에서 접근 할 수 있는 SLAVE, MODE2로 설정

    GPS 와의 프로토콜 ( $GPGGA )

       NMEA 프로토콜 사용

                                            북위           동경           고도          체크섬


         • 위도계산 : 3622.3345 = 36 + (22.3345/60)
         • 경도계산 : 12721.9692 = 127 + (21.9692/60)

캔위성 기본 키트 – 5. 프로토콜 ( to 지상국 – 메시지 )
    사용자 메시지 전송 ( 2017 이후 추가 )
       16 종류의 사용자 메시지 전송 기능
       전송 형태
      크기 (BYTE)       1          1         1        1       MSG_LEN
      내용            0x76        0x00   MSG_TYPE   MSG_LEN    MSG
       MSG_TYPE
        • 0xA0 ~ 0xAF 까지 16개 사용자 정의 타입 가능
        • 0xA0 로 보낼 경우 지상국에서는 MSG_0 로 인식
        • 0xA1 로 보낼 경우 지상국에서는 MSG_1 로 인식

       MSG_LEN
        • 메시지 길이
        • 255 길이 이하이어야 함.

       MSG
        • 송신할 메시지
        • 예) “Hight,110,Temperature,20”

캔위성 기본 키트 – 5. 프로토콜 (to 지상국 – QLOOK)
    사용자 영상 전송 ( 2018 이후 추가 )
       512 x 512 그림 영역에 표시 할 수 있음. (ex. IR Camera 를 지상국에 표시)
       전송 형태

      크기 (BYTE)        1         1       1         1       2    2    MSG_LEN-4
      내용             0x76       0x00   0x80      MSG_LEN   PX   PY     PIXELS

       MSG_TYPE ( 0x80 )

       MSG_LEN
         • 메시지 길이 ( = 2 + 2 + Pixels 길이 )
         • 255 길이 이하이어야 함.
       PX : QuickLook 에서 X 위치 2바이트 ( 값 0x1234 ➔ 보낼때 0x34 0x12 )
       PY : QuickLook 에서 Y 위치 2바이트
       PIXELS : QuickLook 에 표시할 데이터
         • 0 ~ 255 값을 가짐.
         • Ex) 32(0x20), 64(0x40), 위치에 0x01 0x02 0x03 0x04 의 값을 보낸다면
               ( 76 00 80 08 20 00 40 00 01 02 03 04 ) ( hexa 값으로 )

캔위성 기본 키트 – 5. 프로토콜 (to 지상국 - ATLM)
   캔위성에서 지상으로 보내는 방식
      UART( TTL ) 시리얼 통신 ( 115200, N, 8, 1 ) 을 사용하여 전송
      체크섬 데이터를 넣어서 전송 오류에 대응


   ATLM 전송
      8개의 아날로그 텔레메트리 값 전송
      전송 형태

         크기 (BYTE)      1       1       1        1       1     8       1
         내용           0x76     0x00   0x40      0x00     10   ATLMs   CSUM

      ATLMs
        • 8 개의 아날로그 텔레메트리 값
        • 개별 아날로그 텔레메트리는 각각 1 바이트(8비트) 값을 갖음

      CSUM
       • ATLMs 값의 합을 1 바이트로 나타낸 값
         ATLMs[0] + ATLMs[1] + … + ATLMs[6] + ATLMs[7]

캔위성 기본 키트 – 5. 프로토콜 (to 지상국 - DTLM)
   DTLM 전송
      32개의 디지털 텔레메트리(원격검침자료) 값 전송
      전송 형태

          크기 (BYTE)      1       1       1       1         1     4       1
          내용           0x76    0x00    0x48     0x00       04   DTLMs   CSUM

      DTLMs
       • 32 개의 디지털 텔레메트리 값
       • 1비트가 하나의 OFF/ON 값을 표시함
       • 4 바이트로 32개 디지털 텔레메트리 표시

      CSUM
       • DTLMs 값을 모두 XOR 하여 1 바이트로 나타낸 값
         DTLMs[0] xor DTLMs[1] xor DTLMs[2] xor DTLMs[3]

캔위성 기본 키트 – 5. 프로토콜 (to 지상국 - IMU)
   IMU 데이터 전송
      IMU 데이터를 지상으로 전송
      전송 형태


 크기 (BYTE)       1      1       1      1           N        1     2      1      1
 내용            0x76   0x00     0x60   0x00      IMU_DATA   ‘,’   CSUM   0x0D   0x0A
      N         : IMU_DATA 의 길이
      IMU_DATA :
        • IMU 에서 전송하는 IMU 데이터
        • ‘*’ 로 시작하여 ‘\n’또는 ‘\a’이전까지 데이터.
        • 형태 1 : “*,x회전값,y회전값,z축회전값”
        • 형태 2 : “*,x회전값,y회전값,z축회전값,x축가속도값,Y축가속도값,Z축가속도값”
        • 형태 .. : “*Rx,Ry,Rz,Gx,Gy,Gz,Ax,Ay,Az,Mx,My,Mz,Dx,Dy,Dz,T”
      CSUM
        • IMU_DATA 의 합을 cs 라 할때
        • CSUM[0] = cs/16 에 해당하는 문자
        • CSUM[1] = cs%16 에 해당하는 문자
              Ex) cs = 0x48 이면, CSUM[0] = ‘4’, CSUM[1] = ‘8’

          • GPS 에서 전송하는 $GPGGA 또는 $GNGGA GPS 데이터
          • GPS 가 전송한‘$’ 이후 ‘\n’또는 ‘\a’이전까지 데이터.
          • 형태 : “GPGGA,….”또는 “GNGGA,…”
        CSUM
          • GPS_DATA 에서 ‘*’ 문자 이전까지 xor 한 값을 cs 라 하면
          • CSUM[0] = cs/16 에 해당하는 문자
          • CSUM[1] = cs%16 에 해당하는 문자
                Ex) cs = 0x48 이면, CSUM[0] = ‘4’, CSUM[1] = ‘8’
          • CSUM 값은 GPS 자체 정보의 체크섬 데이터와 같게 정의하였음.

      TIME :
        • PC 가 가지고 있는 시각을 4바이트로 초단위로 생성
        • 1970-01-01 00:00:00 ➔ 0 이며 ( 0x00 0x00 0x00 0x00 )
        • 1970-01-01 00:00:01 ➔ 1 임 ( 0x00 0x00 0x00 0x01 ) 순서임.

      XOR :
       • XOR = T0 xor T1 xor T2 xor T3 임.
       • 0x01 0x02 0x03 0x04 의 경우 T0 = 0x01, T1= 0x02, T2 = 0x03 , T3=0x04 임.
       • 0x01 xor 0x02 xor 0x03 xor 0x04
